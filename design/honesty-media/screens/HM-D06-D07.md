# HM-D06 / HM-D07 — Indoor walk (HM-05)

**Ticket:** HM-05 · **Routes:** entry on `/listing/:id`
(`ListingDetailPage`), the walk itself at `/listing/:id/walk` (D20) ·
**Surface today:** `src/pages/ListingDetail.tsx` (entry) and
`src/pages/ListingWalk.tsx` + `src/components/walk/SplatViewer.tsx` (the
walk). **Status:** built, with the deviations in §10.

## 1. Purpose and primary action

Let a guest walk the captured interior of a verified home, with the
honesty badge and disclosure always in reach. Primary action on detail:
**Walk through this home**. In the walk: **Leave the walkthrough**.

## 2. Who

- Public (signed-out included) for an `active` listing with a verified
  scan.
- The owner for their own draft / paused listing (preview).
- Nobody else. A guessed id for a draft, a paused home, a rejected scan
  or a hidden seed row is a 404 from the walkthrough endpoint and the
  existing "We couldn't find this home." page.

## 3. Layout

### Entry on `/listing/:id` (HM-D06)

Directly under the gallery, before "About this home", a new section
`h2` "Walk through this home" (rendered only when `listing.honesty` is
non-null):

**Desktop.** Two columns inside a `Card`: left, the poster still (a real
captured frame, 16:9, `ListingPhoto`) with **Walk through this home**
overlaid at the bottom-left as a normal `ButtonLink` (not an icon);
right, the badge full form as a `StatusPill tone="brand"` line, then
"Captured {date}", the coverage line, and a disclosure `<details>`
titled **About this walkthrough** containing
[journeys §1.2](../JOURNEYS-AND-COPY.md#12-guest-disclosure).

**Phone.** Stacked: poster with the button beneath it (full width),
badge short form, captured date, coverage, then the collapsed
**About this walkthrough**.

When `listing.honesty` is null the section is absent. There is no
"walkthrough coming soon" for guests; for the owner, the existing
preview banner gets one extra sentence (§5).

### The walk at `/listing/:id/walk` (HM-D07)

Focused shell (`focused`, `backTo=/listing/:id`, `backLabel="Home
details"`), `h1` visually small in the top bar: "{title} — walkthrough".
The viewport below the bar is the canvas. Chrome:

- Top bar: Back, `h1`, the badge (full on ≥ 650 px, short below) as
  text, and **About this walkthrough** (opens a `Dialog` with the
  disclosure, captured date and coverage).
- Bottom-left: on-screen move controls (four ≥ 48 px buttons) on touch
  devices; hidden when a keyboard is detected but always reachable via
  a **Controls** button that shows the keyboard map.
- Bottom-right: **Step outside** (HM-06 only, when approach exists) and
  **Leave the walkthrough**.
- First run: a dismissible overlay with the control map (§5). Dismissed
  state is a per-viewer convenience in `localStorage` via
  `src/lib/storage.ts`; absence of storage just shows it again.

Owner preview adds the existing warning banner above the canvas:
"You're previewing your draft listing." + "Guests will see this walk
once the home is published."

## 4. States

| State | Behaviour |
|---|---|
| Loading endpoint | Skeleton canvas; sr-only "Loading the walkthrough" |
| Loading artifact | A text progress line "Loading the walkthrough… 12 MB of 38 MB" (tabular numerals), `role="status"`, updated at most every second; no spinner-only |
| Ready | Camera at the worker's chosen start pose, **stationary**. Nothing moves until the guest moves it |
| `prefers-reduced-motion` | Default view is a stills grid (worker-selected frames, ≥ 6, 4:3) with the caption "Stills from the host's walk" and a **Show the 3D walkthrough** opt-in; once shown, camera moves only on input, no easing animations, no auto-orbit |
| No WebGL / WebGL context lost | Stills grid plus the locked sentence "This walkthrough needs a newer browser. Here are stills from the host's walk." No retry loop; a **Try again** re-checks once |
| Artifact fetch failed | `StatusMessage tone="danger"` "We couldn't load the walkthrough." with **Try again** and the stills grid underneath if stills loaded |
| 404 | The listing not-found page |
| Signed URL expired mid-walk | Re-request the endpoint silently once; if that fails, the fetch-failed state |
| Low memory / slow device | Load the compressed artifact first; the viewer never upsamples or fills; if the compressed artifact fails to decode, stills |

## 5. Copy

- Section `h2`: "Walk through this home"
- Button: **Walk through this home** / in-walk **Leave the walkthrough**
- Control map overlay: "Look around: drag, or arrow keys · Move:
  on-screen arrows, or W A S D · Leave: Esc or Back" with **Got it**.
- Stills caption: "Stills from the host's walk"
- Owner preview line as §3.
- Badge, disclosure, captured date, coverage: locked strings.

## 6. What the server must have decided already

- `listing.honesty` is present only when the listing is `active` and
  `scan_verified_at` is set (or the owner is asking).
- `GET /api/listings/:id/walkthrough` signs short-lived URLs for the
  **mask-applied** artifact and the stills; it never returns a bucket
  path or the raw prefix, and returns 404 for anything unverified
  unless the owner is asking, in which case `ownerPreview: true`.
- The worker chose the start pose and the stills; the browser has no
  say in what is "representative".

## 7. Accessibility

- Exactly one `h1`; focus lands on it via `RouteAnnouncer`.
- The canvas is `role="img"` with `aria-label` "3D walkthrough of
  {title}, captured by the host"; all movement is also possible from
  the on-screen buttons and keyboard; no pointer-only action.
- Escape leaves the walk (with the dialog closed first, per the `Dialog`
  contract).
- The disclosure dialog traps focus and returns it to its trigger.
- Reduced motion honoured as §4; nothing autoplays.
- Contrast of chrome over the canvas: chrome sits on an opaque canvas
  surface strip, not over the render.

## 8. Hard stops

- Never load anything for a `failed` / `rejected` scan; never a
  "preview splat"; never a generated fill when the artifact is partial.
- Never put third-party street imagery, a map vendor, or an ad inside
  the indoor viewer.
- Never expose an unsigned artifact URL or the raw upload prefix.
- Never autoplay a camera move.

## 9. Tests

- HTTP: walkthrough endpoint 404 matrix (draft, paused, rejected, seed,
  guessed id) and owner preview.
- Playwright (CI, no WebGL): the stills fallback with the locked
  sentence; the disclosure dialog; reduced-motion default via
  `emulateMedia`; owner preview banner; Escape leaves.
- Manual: the 3D walk on a WebGL phone and desktop; report device and
  result, never "passed" from CI.

## 10. As built (HM-05)

- **The renderer is Spark 2.2.0 + Three.js 0.186.0**, both MIT, both lazy.
  The viewer chunk is imported only after a real WebGL context probe has
  succeeded, so a guest without one downloads no renderer at all.
- **The poster and the stills are the worker's frames**, signed per request
  through `GET /listings/:id/walkthrough`. Listing detail carries one signed
  poster in `listing.honesty`; signing is a local HMAC, so it costs no
  round trip.
- **The compressed artifact is the one that loads.** The plain splat is a
  fallback only when the worker made no compressed one; the viewer never
  upsamples and there is no "load the big one on a fast connection" path.
- **Which scan is live is a listing column** (`scan_verified_at`,
  `verified_scan_id`), written only by the transitions. This is also what
  unblocks the re-mask deferral in [HM-D05 §10](HM-D05.md): a new pass can
  run while the listing keeps pointing at the old verified scan.
- **`app_user` lost its table-level UPDATE on `listings`** in favour of a
  column list, because those two columns must not be a host's to write.
  `status` is still in the list; D04 takes it in HM-08.
- **No "Step outside"** — that is HM-06's approach, and there is nothing to
  step out to yet.
- **Not verified here:** the 3D walk itself. This sandbox has no GPU, so CI
  exercises the stills and reduced-motion paths and the 404 matrix. The
  walk needs a run on a real WebGL phone and desktop before it is called
  working, per §9.
